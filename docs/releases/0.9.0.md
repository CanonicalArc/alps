# ALPS 0.9.0

[Japanese translation](../locales/ja/releases/0.9.0.md)

ALPS 0.9.0 is the first public release from [CanonicalArc/alps](https://github.com/CanonicalArc/alps), starting a new repository history. It brings together work descriptions, process models, and the agent work systems that realize them.

## Three self-contained Skills

| Skill | Purpose |
| --- | --- |
| [design-process-description](../../skills/design-process-description/SKILL.md) | Clarify the meaning, observable success conditions, relationships, and applicable conditions of work. |
| [design-agent-work-system](../../skills/design-agent-work-system/SKILL.md) | Design the agents, tools, information resources, and environment that realize the work, including implementation and verification within the request. |
| [create-process-models](../../skills/create-process-models/SKILL.md) | Organize related work and shared I/O definitions into one model Plugin, including canonical files and verification. |

Each Skill contains its own guidance and references and works independently. They can be combined by passing a description of the work between them. The Plugin includes English sources, Japanese translations, and the service-assessment example as supporting material.

## One model, one Plugin

The [model format](../../skills/create-process-models/references/model-format.md) defines ALPS model profile version 1. `plugin.json` explicitly lists model members; each process Markdown document owns its complete description, identifier, display title, and I/O; `references/artifacts/<id>.md` defines the shared information items, products, and services. Agent Skills use `skills/<name>/SKILL.md`, while other work, including human work, can use ordinary Markdown.

Registered process documents require a nonblank string `metadata.title`. Declared `metadata.inputs` and `metadata.outputs` are JSON arrays of type identifiers encoded as strings. Concrete artifact locations and execution settings belong in optional workspace configuration.

A graph is a projection of these sources, and the model can contain cycles. I/O relationships do not prescribe execution order or establish approval, readiness, or success. Criteria, policies, and requirements retain their governing meaning and applicability as Controls in the source descriptions. There is no separate Controls metadata field or edge category, and no duplicate model file or type registry.

Profile version `1`, ALPS release version `0.9.0`, and each created model Plugin's own release version are separate. A successful package check does not demonstrate successful execution of the modeled work.

## Distribution and verification

The release includes the Agent Plugins manifest and Claude, Cursor, and Codex adapters. The READMEs explain how to choose a Skill, provide a model-creation request example, and identify the generated sources.

Repository checks cover Skill and Plugin formats, distribution boundaries, translation source hashes, release references, and relative links. The service-assessment example requires Python 3.10 or later and compares decimal duration limits and error-count ratios exactly. Reported JSON numbers may be rounded, while Boolean checks are calculated before that conversion. Mechanical checks, semantic review, respect for requirements and authority, and work-system effectiveness remain distinct judgments.

## Installation

Install from `CanonicalArc/alps` using the [README instructions](../../README.md#install), then reload the client. Confirm that all three Skills are discoverable and their reference links open. Keep each Skill's entire directory when distributing it individually.

ALPS remains in initial development under the [version policy](../versioning.md). Record the published `v0.9.0` tag and its resolved commit SHA for reproducibility. The public release history is in the [changelog](../../CHANGELOG.md).
