# ALPS 0.9.0

[English source](../../../releases/0.9.0.md)

ALPS 0.9.0は、[CanonicalArc/alps](https://github.com/CanonicalArc/alps)からの最初の公開リリースであり、新しいリポジトリ履歴の始まりです。仕事の記述、プロセスモデル、それを実現するエージェント作業システムをまとめて提供します。

## 自己完結した三つのSkill

| Skill | 目的 |
| --- | --- |
| [design-process-description](../../../../skills/design-process-description/references/locales/ja/SKILL.ja.md) | 仕事の意味、観察可能な成功条件、関係、適用条件を明確にする。 |
| [design-agent-work-system](../../../../skills/design-agent-work-system/references/locales/ja/SKILL.ja.md) | 仕事を実現するエージェント・ツール・情報資源・環境を設計する。依頼の範囲内で実装・検証を含む。 |
| [create-process-models](../../../../skills/create-process-models/references/locales/ja/SKILL.ja.md) | 関係する仕事と共有する入出力定義を、一つのモデルPluginにまとめる。正本の作成と検証を含む。 |

各Skillは自身の案内と参照資料を内包し、独立して機能します。組み合わせる場合は、仕事の記述を受け渡します。Pluginには英語原文、日本語訳、補助資料としてのサービス評価の実例を含めます。

## 一つのモデルを一つのPluginに

[モデル形式](../../../../skills/create-process-models/references/locales/ja/model-format.md)は、ALPSモデルプロファイルの版1を定めます。`plugin.json`にモデルの構成員を明示し、各プロセスMarkdownを記述の全文・識別子・表示名・入出力の正本とし、`references/artifacts/<id>.md`で共有する情報項目・製品・サービスを定義します。Agent Skillは`skills/<name>/SKILL.md`を使い、人の仕事など、それ以外の仕事には通常のMarkdownを使えます。

登録されたプロセス文書には、空白だけではない文字列の`metadata.title`が必要です。宣言する`metadata.inputs`と`metadata.outputs`は、型識別子のJSON配列を文字列として符号化します。具体的な成果物の配置と実行設定は、任意のワークスペース設定で扱います。

グラフはこれらの正本の投影であり、モデルには循環を含められます。入出力関係だけでは実行順序を指定せず、承認、準備完了、成功を確立しません。基準・方針・要求は、原記述で、仕事を規定する統制事項としての意味と適用可能性を維持します。統制事項専用のメタデータ項目やエッジ区分、重複するモデルファイルや型レジストリは設けません。

プロファイルの版`1`、ALPSのリリース版`0.9.0`、作成する各モデルPlugin自身のリリース版は別です。パッケージの検査に通っても、モデル化した仕事の実行成功を証明するものではありません。

## 配布と検証

Agent Pluginsのmanifestと、Claude、Cursor、Codexのアダプターを含めます。READMEでは、Skillの選び方、モデル作成の依頼例、生成する正本を説明しています。

リポジトリの検査では、SkillとPluginの形式、配布境界、翻訳原文のハッシュ、リリースの参照先、相対リンクを確認します。サービス評価の実例はPython 3.10以降を必要とし、十進数の時間上限とエラー件数の比率を厳密に比較します。出力するJSONの数値には丸めが生じる場合がありますが、判定の真偽値はその変換前に計算します。機械的な検査、意味のレビュー、要求・権限の尊重、作業システムの有効性は、別々の判断として扱います。

## 導入

[READMEの導入手順](../README.md#導入)に従って`CanonicalArc/alps`から導入し、クライアントを再読み込みしてください。三つのSkillが表示され、それぞれの参照リンクを開けることを確認します。個別に配布する場合は、各Skillのディレクトリ全体を保持してください。

ALPSは[版管理方針](../versioning.md)に基づく初期開発段階です。再現性のため、公開された`v0.9.0`タグと、そのタグが指すコミットSHAを記録してください。公開リリースの履歴は[CHANGELOG](../../../../CHANGELOG.md)に記載しています。
